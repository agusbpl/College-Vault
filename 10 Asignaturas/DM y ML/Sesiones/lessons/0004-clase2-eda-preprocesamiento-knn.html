Módulo 1

Machine Learning vs. Estadística Clásica y el Ciclo Metodológico CRISP-DM

En la práctica profesional y académica, suele existir confusión entre la inferencia estadística clásica y el aprendizaje automático moderno. La cátedra establece una distinción epistemológica nítida:

Axioma Fundamental: "La estadística busca comprender el mundo a partir de los datos mediante inferencia rigurosa; el Machine Learning busca predecir el comportamiento futuro generalizando patrones."
Dimensión Estadística Clásica Machine Learning
Objetivo Principal Inferencia: explicar la relación causal o asociativa entre variables ($p$-valores, intervalos de confianza). Predicción: minimizar el error de generalización en instancias nunca antes vistas.
Dirección del Enfoque $\text{Modelo} \rightarrow \text{Datos}$: Se postula a priori una hipótesis matemática y se evalúan supuestos. $\text{Datos} \rightarrow \text{Modelo}$: Se infiere la estructura subyacente de manera empírica a partir de ejemplos.
Supuestos Requeridos Fuertes: normalidad de residuos, homocedasticidad, independencia estocástica. Débiles o implícitos: no se asume una distribución funcional previa fija.
Interpretabilidad Alta (Modelos de Caja Blanca: regresión logística, tablas de coeficientes). Variable a baja (Modelos de Caja Negra: Ensembles profundos, Redes Neuronales).
Criterio de Evaluación Significancia estadística ($p < 0.05$, $R^2$ ajustado, tests $t$/$F$). Capacidad predictiva en partición de prueba (Accuracy, F1-Score, ROC-AUC, MSE).

El aprendizaje automático no es una panacea. Existen dos restricciones operativas donde su implementación resulta contraproducente o injustificada:

  1. Problemas deterministas o cerrados: Si el fenómeno está regido por una fórmula física unívoca, una especificación contable o un marco regulatorio estricto (ej. cálculo de impuestos patrimoniales o balances contables), programar una lógica deductiva tradicional es $100\%$ exacto, auditable y no sufre de error estocástico.
  2. Ausencia o escasez de datos empíricos: Sin ejemplos representativos del dominio, los algoritmos inductivos colapsan. En tal caso, se debe recurrir a sistemas expertos basados en reglas declarativas.

Módulo 2

La "Vista Minable" y el Análisis Exploratorio de Datos (EDA)

Los sistemas transaccionales (OLTP), las bases de datos SQL relacionales normalizadas en 3FN, los logs y las APIs almacenan datos fragmentados en decenas de tablas heterogéneas. Los algoritmos de Machine Learning tabular (Scikit-Learn, PyTorch tabular, XGBoost) no pueden procesar grafos relacionales directamente: exigen una matriz $X \in \mathbb{R}^{N \times d}$.

Definición de Cátedra: La Vista Minable (Minable View) es una estructura plana y unificada donde:
  • Cada fila representa una única unidad o instancia de análisis (ej. un pasajero del Titanic, un paciente médico, un cliente).
  • Cada columna representa un atributo, característica o feature medido sobre dicha instancia.
  • Se incorpora la variable objetivo (target $y$) en caso de aprendizaje supervisado.

El Análisis Exploratorio persigue 4 objetivos irrenunciables antes de entrenar cualquier estimador:

  • Inspección de integridad: Dimensiones exactas (`df.shape`), tipos de datos (`df.dtypes`) y recuento de nulos (`df.isnull().sum()`).
  • Distribución univariada: Tendencia central, dispersión, asimetría (skewness) y curtosis con `df.describe()`, histogramas y diagramas de caja (boxplots).
  • Análisis bivariado y multivariado: Matrices de correlación de Pearson/Spearman (`sns.heatmap(df.corr())`), pairplots y scatter matrices.
  • Detección de alta dimensionalidad: Cuando el número de variables $d$ supera nuestra capacidad visual 2D/3D, empleamos proyecciones no lineales como t-SNE o PCA (como en la investigación de la cátedra que redujo 561 sensores inerciales de smartphones a 2 dimensiones para clasificar actividades humanas).
Módulo 3

Preprocesamiento de Datos Tabulares: Nulos y Codificación Categórica

Los algoritmos matemáticos como KNN computan distancias geométricas sobre vectores de números reales $\vec{x} \in \mathbb{R}^d$. Un valor nulo (`NaN`) o una cadena de texto (`"male"`, `"Queenstown"`) romperá de inmediato el cálculo matricial.

En el Titanic, por ejemplo, observamos nulos en Age (~20%), Cabin (~77%) y Embarked (~0.2%). Ante un nulo se presentan tres alternativas:

Estrategia Comando Pandas Ventajas & Desventajas Metodológicas
Eliminar Columnas df.drop(columns=['Cabin']) Indicado cuando: la proporción de nulos supera el 60-70% o la variable no posee poder explicativo generalizable (como PassengerId o Ticket).
Eliminar Filas df.dropna() Indicado cuando: se cuenta con abundante volumen de datos y los registros faltantes son marginales (<5%). Riesgo: sesgar la muestra si los nulos no son aleatorios (Missing Not at Random - MNAR).
Imputación (Reemplazo) df['Age'].fillna(median) Peligro latente: Reemplazar ciegamente por la media o mediana deforma la varianza y puede crear combinaciones absurdas en el espacio de características. En escenarios avanzados se emplean modelos predictivos (KNNImputer o IterativeImputer).

No todas las variables de texto poseen la misma naturaleza semántica. Confundir la técnica de codificación introduce un sesgo métrico artificial destructivo para clasificadores basados en distancias como KNN:

Comparativa Matemática: Ordinal Encoding vs. One-Hot Encoding

A. Categorical / Ordinal Encoding: Asigna números enteros respetando una relación de orden natural: $$\text{Nivel de Educación}: \quad \{\text{Primaria}: 0, \; \text{Secundaria}: 1, \; \text{Universitario}: 2\}$$ Propiedad matemática: La distancia métrica tiene sentido real: $d(0, 1) = 1$, $d(0, 2) = 2$ (un universitario está a 2 niveles de primaria).

B. One-Hot Encoding (Variables Nominales sin Orden): Si asignáramos a la ciudad de embarque Embarked: $\{\text{Southampton}: 0, \; \text{Cherbourg}: 1, \; \text{Queenstown}: 2\}$, el algoritmo KNN calcularía: $$d(\text{Southampton}, \text{Queenstown}) = |0 - 2| = 2 \quad > \quad d(\text{Southampton}, \text{Cherbourg}) = |0 - 1| = 1$$ ¡Esto induciría una falsa proximidad geográfica o socioeconómica inexistente en la realidad! Con One-Hot Encoding generamos tres vectores ortogonales en $\mathbb{R}^3$: $$\vec{v}_S = [1, 0, 0], \quad \vec{v}_C = [0, 1, 0], \quad \vec{v}_Q = [0, 0, 1]$$ $$\forall i \neq j, \quad d_{\text{Euclidea}}(\vec{v}_i, \vec{v}_j) = \sqrt{(1-0)^2 + (0-1)^2 + (0-0)^2} = \sqrt{2} \approx 1.414$$ Todos los puertos quedan equidistantes entre sí en el hiperespacio.

Módulo 4

Escalamiento de Características y la Prevención del "Data Leakage"

Como vimos en la Lección 01, la distancia euclidiana entre dos pasajeros $p$ y $q$ en el Titanic es: $$d(p, q) = \sqrt{(Age_p - Age_q)^2 + (Fare_p - Fare_q)^2 + \sum (Embarked_{p,i} - Embarked_{q,i})^2}$$ La variable Fare (tarifa en libras) oscila entre $0$ y $512$, mientras que Age oscila entre $0.42$ y $80$, y las columnas de Embarked valen $0$ o $1$. Sin escalamiento, una diferencia de £100 en la tarifa eclipsará por completo cualquier diferencia de 30 años de edad.

⚠️ La Trampa Mortal del Principiante: Fuga de Datos (Data Leakage)
Nunca, bajo ninguna circunstancia, se debe aplicar scaler.fit(X) sobre todo el dataset antes de dividir en Train y Test. Al calcular la media $\mu$ y la desviación estándar $\sigma$ usando todas las instancias, la información del conjunto de prueba se filtra imperceptiblemente en el conjunto de entrenamiento. Esto produce métricas de evaluación engañosamente optimistas que colapsan miserablemente en producción.
Regla de Oro de la Cátedra para Preprocesamiento
Python / Scikit-LearnProtocolo Correcto
# 1. DIVIDIR PRIMERO:
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y)

# 2. AJUSTAR EL ESCALADOR EXCLUSIVAMENTE CON TRAIN:
scaler = StandardScaler()
scaler.fit(X_train)  # <-- Solo calcula mu_train y sigma_train

# 3. TRANSFORMAR AMBOS CON LOS PARÁMETROS DE TRAIN:
X_train_scaled = scaler.transform(X_train)
X_test_scaled  = scaler.transform(X_test)  # <-- Test es transformado a ciegas

Evaluación de Modelos: Overfitting, Underfitting y Particiones Avanzadas

¿Qué significa "aprender" en Machine Learning? La cátedra utiliza la clásica analogía pedagógica del examen escolar:

Analogía del Examen y la Memoria: Si un profesor enseña a multiplicar usando 10 ejercicios en clase y en el examen final toma exactamente esos mismos 10 ejercicios, un estudiante con memoria prodigiosa obtendrá un $10/10$ sin haber comprendido jamás el algoritmo de la multiplicación. Para verificar si adquirió el concepto general, el examen debe evaluar 5 ejercicios completamente nuevos.
Estado del Modelo Accuracy en Train Accuracy en Test Diagnóstico Metodológico
Underfitting (Subajuste) Bajo (~55%) Bajo (~53%) Modelo demasiado simple (alto sesgo / high bias) o variables insuficientes para capturar la frontera.
Modelo Equilibrado (Óptimo) Alto (~83%) Alto (~81%) Buena capacidad de generalización. Captura el patrón estructural ignorando el ruido muestral.
Overfitting (Sobreajuste) Casi perfecto (~99-100%) Pobre (~68-71%) Modelo hipercomplejo (alta varianza / high variance). Memorizó el ruido y las peculiaridades del conjunto de entrenamiento.

No siempre es admisible una división aleatoria estándar $80/20$. La cátedra destaca tres escenarios experimentales reales donde violar el criterio de dominio destruye la validez del experimento:

1. División Espacial (Geográfica)

Ejemplo: Estimación de ingresos con imágenes satelitales en Buenos Aires (Abbate, Ronchetti et al., 2024). Si se mezcla aleatoriamente píxeles contiguos, Train y Test compartirán la misma manzana, produciendo autocorrelación espacial espuria. La división debe hacerse por comunas o cuadrantes aislados.

2. División Temporal (Series Temporales)

Ejemplo: Predicción de radiación solar global (Iturbide, Ronchetti et al., 2023). El futuro no puede usarse para predecir el pasado. El conjunto de Train debe componerse de los meses/años precedentes y el de Test de los periodos subsiguientes.

3. División por Sujeto Experimental

Ejemplo: Reconocimiento de Lengua de Señas Argentina - LSA (Ronchetti et al., 2016). Si un mismo sujeto ejecuta 20 repeticiones de una seña y repartimos 16 en Train y 4 en Test, el modelo memorizará los rasgos físicos del participante en vez de la seña. La partición debe ser Leave-One-Subject-Out.

Una sola partición aleatoria de prueba posee alta variabilidad debido al componente estocástico de la selección muestral. Para obtener una estimación insesgada y robusta, promediamos múltiples ejecuciones:

Formulación Estadística de Validación Cruzada
$$\bar{A} = \frac{1}{K} \sum_{k=1}^K A_k \quad \pm \quad s = \sqrt{\frac{1}{K-1} \sum_{k=1}^K (A_k - \bar{A})^2}$$
  1. K-Fold: El dataset se divide en $K$ particiones contiguas no solapadas. Se entrena con $K-1$ y se evalúa con la restante, repitiendo $K$ veces rotativas.
  2. Stratified K-Fold: Variante obligatoria para clases desbalanceadas: garantiza que cada fold posea la misma proporción exacta de cada clase que el dataset entero.
  3. ShuffleSplit (Monte Carlo CV): Realiza $N$ particiones aleatorias independientes con reemplazo global, permitiendo desacoplar el número de iteraciones del tamaño del conjunto de prueba.

El Algoritmo KNN en Acción: El Caso Titanic y la Dinámica de K

El clasificador K-Nearest Neighbors es un aprendiz perezoso (lazy learner): no computa una función paramétrica analítica durante el entrenamiento. En su lugar, memoriza los puntos en el hiperespacio y al predecir una nueva consulta $X$, ubica sus $K$ vecinos más próximos por distancia euclidiana y somete el veredicto a votación por mayoría.

Para encadenar la normalización y el clasificador dentro de un bucle de validación cruzada sin una sola gota de fuga de datos, la cátedra utiliza la clase Pipeline de Scikit-Learn:

Python · Script Oficial UNLPTitanic_KNN.ipynb
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import ShuffleSplit, cross_validate

# 1. Definir el clasificador
K = 5
modelo = KNeighborsClassifier(n_neighbors=K)

# 2. Encapsular en Pipeline: StandardScaler + KNN
# El pipeline garantiza que en CADA split de validación cruzada,
# scaler.fit() se ejecute SOLO sobre las muestras de entrenamiento de ese fold.
pipeline = Pipeline([
    ('scaler', StandardScaler()),
    ('knn', modelo)
])

# 3. Configurar validación cruzada con 10 repeticiones aleatorias (ShuffleSplit)
ss = ShuffleSplit(n_splits=10, test_size=0.2, random_state=42)

# 4. Computar métricas en Train y Test simultáneamente
cv_results = cross_validate(pipeline, X, y, cv=ss, scoring=['accuracy'], return_train_score=True)

mean_train = cv_results['train_accuracy'].mean()
std_train  = cv_results['train_accuracy'].std()
mean_test  = cv_results['test_accuracy'].mean()
std_test   = cv_results['test_accuracy'].std()

print(f"Accuracy TRAIN: {mean_train:.2f} (+/- {std_train:.2f})")
print(f"Accuracy TEST:  {mean_test:.2f} (+/- {std_test:.2f})")
