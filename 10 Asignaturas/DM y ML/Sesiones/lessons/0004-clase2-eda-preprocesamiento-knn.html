Módulo 1

Machine Learning vs. Estadística Clásica y el Ciclo Metodológico CRISP-DM

En la práctica profesional y académica, suele existir confusión entre la inferencia estadística clásica y el aprendizaje automático moderno. La cátedra establece una distinción epistemológica nítida:

Axioma Fundamental: "La estadística busca comprender el mundo a partir de los datos mediante inferencia rigurosa; el Machine Learning busca predecir el comportamiento futuro generalizando patrones."
Dimensión Estadística Clásica Machine Learning
Objetivo Principal Inferencia: explicar la relación causal o asociativa entre variables ($p$-valores, intervalos de confianza). Predicción: minimizar el error de generalización en instancias nunca antes vistas.
Dirección del Enfoque $\text{Modelo} \rightarrow \text{Datos}$: Se postula a priori una hipótesis matemática y se evalúan supuestos. $\text{Datos} \rightarrow \text{Modelo}$: Se infiere la estructura subyacente de manera empírica a partir de ejemplos.
Supuestos Requeridos Fuertes: normalidad de residuos, homocedasticidad, independencia estocástica. Débiles o implícitos: no se asume una distribución funcional previa fija.
Interpretabilidad Alta (Modelos de Caja Blanca: regresión logística, tablas de coeficientes). Variable a baja (Modelos de Caja Negra: Ensembles profundos, Redes Neuronales).
Criterio de Evaluación Significancia estadística ($p < 0.05$, $R^2$ ajustado, tests $t$/$F$). Capacidad predictiva en partición de prueba (Accuracy, F1-Score, ROC-AUC, MSE).

El aprendizaje automático no es una panacea. Existen dos restricciones operativas donde su implementación resulta contraproducente o injustificada:

  1. Problemas deterministas o cerrados: Si el fenómeno está regido por una fórmula física unívoca, una especificación contable o un marco regulatorio estricto (ej. cálculo de impuestos patrimoniales o balances contables), programar una lógica deductiva tradicional es $100\%$ exacto, auditable y no sufre de error estocástico.
  2. Ausencia o escasez de datos empíricos: Sin ejemplos representativos del dominio, los algoritmos inductivos colapsan. En tal caso, se debe recurrir a sistemas expertos basados en reglas declarativas.

Módulo 2

La "Vista Minable" y el Análisis Exploratorio de Datos (EDA)

Los sistemas transaccionales (OLTP), las bases de datos SQL relacionales normalizadas en 3FN, los logs y las APIs almacenan datos fragmentados en decenas de tablas heterogéneas. Los algoritmos de Machine Learning tabular (Scikit-Learn, PyTorch tabular, XGBoost) no pueden procesar grafos relacionales directamente: exigen una matriz $X \in \mathbb{R}^{N \times d}$.

Definición de Cátedra: La Vista Minable (Minable View) es una estructura plana y unificada donde:
  • Cada fila representa una única unidad o instancia de análisis (ej. un pasajero del Titanic, un paciente médico, un cliente).
  • Cada columna representa un atributo, característica o feature medido sobre dicha instancia.
  • Se incorpora la variable objetivo (target $y$) en caso de aprendizaje supervisado.

El Análisis Exploratorio persigue 4 objetivos irrenunciables antes de entrenar cualquier estimador:

  • Inspección de integridad: Dimensiones exactas (`df.shape`), tipos de datos (`df.dtypes`) y recuento de nulos (`df.isnull().sum()`).
  • Distribución univariada: Tendencia central, dispersión, asimetría (skewness) y curtosis con `df.describe()`, histogramas y diagramas de caja (boxplots).
  • Análisis bivariado y multivariado: Matrices de correlación de Pearson/Spearman (`sns.heatmap(df.corr())`), pairplots y scatter matrices.
  • Detección de alta dimensionalidad: Cuando el número de variables $d$ supera nuestra capacidad visual 2D/3D, empleamos proyecciones no lineales como t-SNE o PCA (como en la investigación de la cátedra que redujo 561 sensores inerciales de smartphones a 2 dimensiones para clasificar actividades humanas).

El Algoritmo KNN en Acción: El Caso Titanic y la Dinámica de K

El clasificador K-Nearest Neighbors es un aprendiz perezoso (lazy learner): no computa una función paramétrica analítica durante el entrenamiento. En su lugar, memoriza los puntos en el hiperespacio y al predecir una nueva consulta $X$, ubica sus $K$ vecinos más próximos por distancia euclidiana y somete el veredicto a votación por mayoría.

Para encadenar la normalización y el clasificador dentro de un bucle de validación cruzada sin una sola gota de fuga de datos, la cátedra utiliza la clase Pipeline de Scikit-Learn:

Python · Script Oficial UNLPTitanic_KNN.ipynb
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import ShuffleSplit, cross_validate

# 1. Definir el clasificador
K = 5
modelo = KNeighborsClassifier(n_neighbors=K)

# 2. Encapsular en Pipeline: StandardScaler + KNN
# El pipeline garantiza que en CADA split de validación cruzada,
# scaler.fit() se ejecute SOLO sobre las muestras de entrenamiento de ese fold.
pipeline = Pipeline([
    ('scaler', StandardScaler()),
    ('knn', modelo)
])

# 3. Configurar validación cruzada con 10 repeticiones aleatorias (ShuffleSplit)
ss = ShuffleSplit(n_splits=10, test_size=0.2, random_state=42)

# 4. Computar métricas en Train y Test simultáneamente
cv_results = cross_validate(pipeline, X, y, cv=ss, scoring=['accuracy'], return_train_score=True)

mean_train = cv_results['train_accuracy'].mean()
std_train  = cv_results['train_accuracy'].std()
mean_test  = cv_results['test_accuracy'].mean()
std_test   = cv_results['test_accuracy'].std()

print(f"Accuracy TRAIN: {mean_train:.2f} (+/- {std_train:.2f})")
print(f"Accuracy TEST:  {mean_test:.2f} (+/- {std_test:.2f})")

Control Teórico Rápido Cuestión 01 / 02

¿Por qué normalizar antes de un `train_test_split` invalida el rigor del experimento científico?

A Porque la función `StandardScaler` de Scikit-Learn arroja un error de ejecución si se invoca sobre todo el dataframe.
B Porque al computar la media $\mu$ y varianza $\sigma^2$ con todo el conjunto, la distribución de los datos de test contamina el entrenamiento (Data Leakage), inflando ficticiamente la precisión.
C Porque las variables categóricas como el puerto de embarque se convierten automáticamente en nulos.
Control Teórico Rápido Cuestión 02 / 02

En un problema de reconocimiento de Lengua de Señas Argentina (LSA) con 10 personas señando, ¿cuál es la partición metodológicamente correcta?

A Un `ShuffleSplit` aleatorio al 80/20 sobre todas las muestras de video.
B Una partición temporal tomando los primeros 8 segundos de cada seña para Train y los últimos 2 segundos para Test.
C Una partición por sujeto experimental (Leave-One-Subject-Out), donde los videos de 8 personas entrenan el modelo y 2 personas completas se reservan exclusivamente para el testeo.
