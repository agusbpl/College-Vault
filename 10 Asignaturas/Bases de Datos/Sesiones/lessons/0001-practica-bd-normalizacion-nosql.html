1. Identificación de Dependencias Funcionales y 2FN

Dado el esquema de ventas:

Pedido(idPedido, idProducto, fecha, idCliente, nombreCliente, nombreProducto, precioUnitario, cantidad) PK: (idPedido, idProducto)

¿Qué afirmación es correcta respecto a su estado de normalización?

A. Está en 2FN porque no existen atributos multivaluados y cada celda es atómica.
B. Viola la 2FN porque nombreProducto depende solo de idProducto, que es parte de la PK.
C. Viola la 1FN porque hay dependencia transitiva entre idCliente y nombreCliente.
D. Cumple 3FN ya que todos los atributos no primos dependen funcionalmente de la fecha.
Respuesta Modelo: B. Para estar en 2FN, todo atributo no clave debe depender por completo de la clave primaria compuesta. Aquí, idProducto → nombreProducto, precioUnitario es una dependencia parcial.
Alta

2. Eliminación de Dependencias Transitivas (3FN)

Dado el esquema: Cliente(dni, nombre, apellido, códigoPostal, ciudad) con PK dni, donde códigoPostal → ciudad:

A. Está en 3FN porque la clave primaria es simple (un solo atributo).
B. Viola 3FN debido a que existe una dependencia transitiva (dni → códigoPostal → ciudad).
C. Viola 2FN porque ciudad no depende de una clave candidata alternativa.
D. Se normaliza agrupando dni y ciudad en una nueva tabla puente muchos a muchos.
Respuesta Modelo: B. Viola 3FN por dependencia transitiva. Se descompone en Cliente(dni, nombre, apellido, códigoPostal(FK)) y Localidad(códigoPostal, ciudad).

3. MongoDB: Consultas y Agregaciones

¿Qué consulta devuelve los libros disponibles con año de publicación superior a 1980 en la colección libros?

A. db.libros.find({ disponible: true, anio: { $gt: 1980 } })
B. db.libros.select({ disponible: true, anio: { $higher: 1980 } })
C. db.libros.filter({ $and: [ { disponible: 1 }, { anio: 1980 } ] })
D. db.libros.aggregate([ { $project: { disponible: true, anio: { $gte: 1980 } } } ])
Respuesta Modelo: A. $gt es el operador estándar de comparación para "greater than" en MongoDB.
Alta

4. Redis: Estructuras y Comandos

Si ejecutas el comando INCR contador_visitas sobre una clave que aún no existe en Redis:

A. Arroja un error de tipo NIL o KeyNotFoundError.
B. Inicializa la clave en 0 antes de realizar la operación y devuelve 1.
C. Setea el valor como string vacío y devuelve 0.
D. Deja la clave en estado bloqueante esperando una escritura previa.
Respuesta Modelo: B. En Redis, si la clave no existe para INCR, se asume un valor inicial de 0 y se incrementa inmediatamente a 1.
Alta

5. Bases de Datos de Grafos (Neo4j)

En el modelo de datos de grafos de propiedades utilizado por Neo4j, las aristas (relaciones):

A. Son siempre implícitas y se resuelven mediante joins en tiempo de ejecución.
B. Son entidades de primer orden dirigidas, con tipo y pueden contener propiedades propias.
C. Solo pueden conectar nodos del mismo tipo o etiqueta (label).
D. No admiten direccionamiento ni ponderación de pesos.
Respuesta Modelo: B. En Labeled Property Graph (LPG), las relaciones están dirigidas, tienen nombre/tipo y almacenan propiedades clave-valor (ej. fecha, peso).
